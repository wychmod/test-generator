# v2.2.0 — 知识库辅助层 + 生态标准对齐 + 版本单一数据源

> **内容已收口，仅剩发布动作。** 发布当日把 `status` 改为 `stable` 并补 `released` 日期，
> 同时执行 `npm publish` 与 GitHub Release。

## 新增（Added）

- **本地知识库 `knowledge/`**（v1 触发式 BM25）：`build_index.py` 零依赖索引构建（自写分词 + 2/3/4-gram 回退）、`search.py` 触发词检索、`llm-ingest-template.md` 手动录入模板。
- **`knowledge/scripts/ingest.py`**：通过用户自配置的 `TEST_GEN_LLM_CMD` 命令自动抽取知识条目，不绑定任何 LLM SDK。
- **`scripts/incremental_code_scan.py`**：解析 unified diff、提取新增代码行、按 token 重叠匹配 PRD 需求 ID，并用 4 条规则标记潜在 bug（硬编码密钥 / 裸 `except` / 动态执行 / SQL 字符串拼接）。
- **`docs/` 文档中心**：架构、开发、运维、质量与 changelog 五个分区。
- **`devtools/sync_version.py`**：以 `skill.manifest.json` 的"版本"为唯一数据源，同步全部身份版本标记；`--check` 报漂移，`--write` 回写。
- **`devtools/gen_plugin_manifests.py`** 与 `.claude-plugin/plugin.json` / `marketplace.json`：支持 `/plugin marketplace add wychmod/test-generator` 一行安装。`skills: ["."]` 让仓库根目录直接作为 skill 目录，**无需迁移任何文件**。
- **根 `AGENTS.md`**：面向 AI agent 的仓库操作说明（≤100 行）。Codex / Cursor / Copilot / Gemini CLI / Windsurf 等 20+ 工具原生读取；Claude Code 在无 `CLAUDE.md` 时亦回退读取。
- **`references/` 渐进披露层**：`delivery-protocol.md`、`quality-review.md`、`knowledge-base-usage.md`。
- **`.github/workflows/ci.yml`**：版本同步、插件清单、三层审计与两套测试全部纳入必跑项。
- **新增测试**：`test/adapter-routing.test.js`（11 例，覆盖 manifest ↔ ENVIRONMENTS ↔ adapters 三方一致与大小写冲突保护）、`test/test_sync_version.py`、`test/test_gen_plugin_manifests.py`。Python 用例由 15 增至 36。
- `test-generator activate all`：一次性激活全部受支持宿主。

## 改动（Changed）

- **`SKILL.md` 从 6,494 字符瘦身到 4,355**（正文 6,045 → 3,906，**-35%**）。执行细则下沉到 `references/`，入口只保留能力声明、触发时机、执行规则、质量门禁与资源路由，回归"入口即路由"的标准模型。
- **版本号收敛到单一数据源**：此前 `SKILL.md` / `skill.manifest.json` 停在 2.1.0，而 `package.json` / `README` 已是 2.2.0；一次性修正 **47 处**身份标记。
- `devtools/skill_quality_audit.py` 的版本检查不再硬编码 `"2.1.0"`，改为从 manifest 动态取值 —— 审计脚本本身不再成为漂移源。
- `devtools/capability_audit.py` 新增 `version_sync` 检查并复用同一个同步器，**版本漂移在打包预检阶段即被拦截**。
- `npm test` 只跑 Node 测试；新增 `npm run test:python` 跑 Python 测试。
- `package.json` 的 `files` 与 `skill.manifest.json` 的运行时文件清单补入 `references`。
- `DISTRIBUTION.md` 把 `knowledge/` 相关条目从「开发工具处理」拆到独立的「运行时资产（进入分发包）」章节，消除"表头说不进包、行内说进包"的自相矛盾。
- `HOST_COMPATIBILITY.md` 补充大小写不敏感文件系统上的入口冲突说明与已知取舍。

## 修复（Fixed）

- **`npm test` 完全无法运行**：`node --test test` 会把 `test` 当作入口模块并报 `MODULE_NOT_FOUND`。改为 `node --test "test/**/*.test.js"`（该写法也避免误捞 `bin/test-generator.js`）。
- **`scripts/prd_reader.py` 副作用式安装依赖**：缺少 `pdfplumber` 时会静默执行 `pip install`，污染宿主解释器、绕过项目依赖策略、在离线环境长时间卡住。改为只输出手动安装指引，并已验证缺依赖路径零写入。
- **`package.json` 自引用依赖**：`dependencies` 依赖了它自己，导致 `node_modules` 内嵌一份 v2.1.0 陈旧副本。删除该依赖块（本包实际零第三方依赖）。
- **OpenClaw 激活会覆盖 canonical `SKILL.md`**：`skill.md` 与 `SKILL.md` 在 Windows / macOS 上是同一个文件，适配器会把 canonical 内容静默冲掉。现改为检测到冲突即跳过写入、保留 canonical，并在 CLI 输出明确提示。
- **`docs/architecture/README.md`** 把已完成的 `pipeline-overview.md` 仍列为"待写"。
- **`docs/architecture/README.md` 的 `version_alignment` 此前处于 fail 状态**：README 第一行 H1 缺 `vX.Y.Z`，现已补齐。
- **悬空引用**：`.harness/AGENTS.md`、`.harness/reins/manifest-keeper/AGENT.md`、`DISTRIBUTION.md` 中指向已搬迁 `PACKAGING.md` 的引用与一个坏链接。
- **PRD 需求抽取误判**：`incremental_code_scan.py` 会把 Python 函数 docstring 识别为需求，已增加 docstring 区间过滤。

## 移除（Removed）

- 移除 `package.json` 的自引用依赖项。
- 移除本地陈旧宿主镜像副本（`.agents/` `.codebuddy/` `.cursor/` `.windsurf/`）与空目录（`.claude/skills` `.qoder/skills` `.trae/skills` `skills/`）；镜像统一由 `test-generator activate` 生成。
- 移除 `devtools/skill_quality_audit.py` 中写死旧版本字面量的 `STALE_VERSION_MARKERS` 清单。
- `PACKAGING.md` 已并入 `docs/operations/packaging.md`，根目录不再保留。
- 移除 `.harness/changelogs/v2.2.0-TEMPLATE.md`（已由本文件取代）。

## 已知限制（Known Limitations）

- **打包层仍是自研的**：`skill.manifest.json` 不在任何生态规范内。客户端识别依赖本版新增的 `.claude-plugin/*`；完整迁移到"单一 `skills/<name>/` 树 + 每客户端 manifest"**尚未进行** —— 该改造会同时触及 manifest 运行时路径、`lib/activation.js`、4 个审计脚本的硬编码路径、`package.json` `files`、文档目录树与 skill 自身资源路由，需分阶段推进。方案见 [`docs/architecture/skill-ecosystem-benchmark.md`](../../docs/architecture/skill-ecosystem-benchmark.md) P1-4。
- **OpenClaw 根级入口在所有平台都会被跳过**：冲突判定基于文件名而非探测文件系统大小写敏感性，以此换取"同一条 `activate` 在 CI 与开发者机器上产出完全一致结果"的可预测性。代价是 Linux 上的 OpenClaw 需读取 `adapters/openclaw/skill.md`。
- **非 Claude 客户端尚无插件清单**：`.codex-plugin/` / `.cursor-plugin/` 等需要各自厂商的清单规范，未在缺乏权威规范的情况下臆造格式。
- **`docs/` 不在任何一致性审计覆盖范围内**，仍存在 v2.1 叙述性引用。
- `knowledge/index.json` 是本地构建产物、不入包，首次使用知识库必须先跑 `build_index.py`。

## 升级注意（Upgrade Notes）

- `SKILL.md` 的执行细则已迁至 `references/`。**宿主若缓存了旧版 `SKILL.md`，需重新激活**（`test-generator activate <host>`）才能拿到新的路由结构。
- 若此前依赖的镜像副本停留在 v2.1（缺少 `knowledge/` 与增量扫描脚本），请重跑 `test-generator activate all`。
- **版本号不要再手工修改**：改 `skill.manifest.json` 的"版本"字段，然后跑 `python devtools/sync_version.py --write`。
- `npm test` 语义已变更：现在只跑 Node 测试；Python 测试请用 `npm run test:python`。
- 新增可选入口：Claude Code 用户可直接 `/plugin marketplace add wychmod/test-generator` → `/plugin install testcase-generator@wychmod-testcase-generator`。
