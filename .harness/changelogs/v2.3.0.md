# v2.3.0 — 生态标准布局 + 版本单一数据源 + 原生安装通路

> **内容已收口，仅剩发布动作。** 发布当日把 `status` 改为 `stable` 并补 `released` 日期，
> 同时执行 `npm publish` 与 GitHub Release。

## 新增（Added）

- **`skills/testcase-generator/` 标准技能树**：技能内容从仓库根迁入 Agent Skills 标准布局，
  客户端可**自动发现**，不再依赖自定义激活流程。仓库根只保留分发元数据、适配层与开发工具。
- **`.claude-plugin/plugin.json` + `marketplace.json`**：支持
  `/plugin marketplace add wychmod/test-generator` → `/plugin install testcase-generator@…`
  一行安装，取代"`npm i` + `activate`"两步通路。
- **`devtools/gen_plugin_manifests.py`**：从 `skill.manifest.json` *生成*客户端插件清单，
  `--check` / `--write` / `--stdout`。清单不再手工维护，也就不会再漂移。
- **`devtools/sync_version.py`**：以 manifest 的"版本"为唯一数据源，同步全部身份版本标记。
- **根 `AGENTS.md`**（85 行）：面向 AI agent 的仓库操作说明。Codex / Cursor / Copilot /
  Gemini CLI / Windsurf 等 20+ 工具原生读取。
- **`references/` 渐进披露层**：`delivery-protocol.md`、`quality-review.md`、`knowledge-base-usage.md`。
- **`.github/workflows/ci.yml`**：7 项必跑检查（版本同步、插件清单、三层审计、双测试套件）。
- **`changelog_exists` 审计项**：当前版本无正式 changelog 即 fail。
- **新增测试**：`test/adapter-routing.test.js`、`test/test_sync_version.py`、
  `test/test_gen_plugin_manifests.py`。Python 用例 15 → 36。

## 改动（Changed）

- **`SKILL.md` 从 6,494 字符瘦身到 4,355**（正文 6,045 → 3,906，**-35%**）。执行细则下沉
  `references/`，入口回归"能力声明 + 触发时机 + 资源路由"。
- **版本号收敛到单一数据源**：此前 `SKILL.md` / `skill.manifest.json` 停在 `2.1.0`，
  而 `package.json` / `README` 已是 `2.2.0`；一次性修正 **47 处**身份标记。
  本版起版本号只改 manifest，其余由同步器回写。
- `devtools/skill_quality_audit.py` 的版本检查不再硬编码 `"2.1.0"`，改为从 manifest 动态取值。
- `devtools/capability_audit.py` 新增 `version_sync` 检查，版本漂移在打包预检阶段即被拦截；
  必需路径检查由 23 项增至 30 项。
- `.claude-plugin/` 的 `plugin.json` **不再声明 `skills` 覆盖字段** —— 标准布局下默认扫描
  已覆盖 `skills/`，省去一个无法在本机验证的字段语义假设。
- **`openclaw` 的本地激活目标由 `skills/testcase-generator` 改为
  `.openclaw/skills/testcase-generator`**（前者现在是 canonical 技能树本身）。
- `npm test` 只跑 Node 测试；Python 测试改用独立脚本：

  ```bash
  npm run test:python
  ```
- `.gitignore`、manifest 运行时文件、`分发排除`、`package_skill.py` 的禁入规则与必需成员、
  4 个审计脚本的路径常量、README / DISTRIBUTION / HOST_COMPATIBILITY / AGENTS.md 的目录树
  与入包清单，全部随技能树迁移同步更新。

## 修复（Fixed）

- **`npm test` 完全无法运行**：`node --test test` 会把 `test` 当作入口模块并报
  `MODULE_NOT_FOUND`。改为 `node --test "test/**/*.test.js"`。
- **`scripts/prd_reader.py` 副作用式安装依赖**：缺少 `pdfplumber` 时会静默执行 `pip install`。
  改为只输出手动安装指引；已验证缺依赖路径零写入。
- **`package.json` 自引用依赖**：`dependencies` 依赖了它自己，导致 `node_modules` 内嵌一份
  v2.1.0 陈旧副本。删除该依赖块（本包实际零第三方依赖）。
- **宿主入口大小写冲突保护**：`skill.md` 在大小写不敏感文件系统上会覆盖 `SKILL.md`。
  `lib/activation.js` 新增基于文件名的冲突检测，冲突时跳过写入并保留技能入口。
  **本版的标准布局让两者不再同层，该冲突实际已消除**，保护保留为纵深防御。
- **`docs/architecture/README.md` 的 `version_alignment` 此前处于 fail 状态**：
  README 第一行 H1 缺 `vX.Y.Z`，已补齐。
- **悬空引用**：`.harness/AGENTS.md`（目录表 + 中文优先铁律 + 一个**坏链接**）、
  `.harness/reins/manifest-keeper/AGENT.md`（2 处）、`DISTRIBUTION.md` 中指向已搬迁
  `PACKAGING.md` 的引用；`.harness/eval/HEALTH_REPORT.md` 指向已删除的发版模板。
- **`DISTRIBUTION.md` 的自相矛盾**：`## 开发工具处理` 表头写"不进入分发包"，却混入了应进包的
  `knowledge/` 文件（行内还写着"进入分发包"）。已拆出独立的「运行时资产」章节。
- **`incremental_code_scan.py` 会把 Python 函数 docstring 识别为需求**（v2.2.0 之后修复）。
- **`test_knowledge_docs.py` 的脆弱断言**：它假定 KB 规则写在 `SKILL.md` 里，
  内容下沉 `references/` 后立即误报；改为断言"文档面"，并新增"入口必须路由到 references"的用例。
- **`marketplace.json` 的市场级描述**：`claude plugin validate` 先对缺失发出告警
  （`metadata.description: No marketplace description provided`）；补齐时又因为在
  **顶层**多写了一份 `description` 而直接报错
  （`root: Unrecognized key: "description"`）。最终确认位置**只能**是
  `metadata.description` —— 该校验器对未知顶层键是**报错而非忽略**，因此"两个位置
  都给更保险"的做法不是冗余，而是会直接弄坏构建。已在 `skill.manifest.json` 新增
  双语 `市场说明` 字段作为单一来源，并加两条测试钉死（描述必须存在；顶层不得出现
  `description`）。插件清单文本取自 `en-US` 侧，该选择已显式化为
  `gen_plugin_manifests.MANIFEST_LANGUAGE`。
- **`npm test` 在 Node 20 上必然失败**：`node --test` 的 glob 参数支持是 **Node v21**
  才加入的，而 CI 固定 Node 20，导致"本地（Node 22）能过、CI 全红"。已改为显式文件列表，
  并新增 `test/test-discovery.test.js` 守卫（断言脚本与实际测试文件集合一致、且不含 glob
  字符）；CI 同时引入 **Node 18/20/22 矩阵**，让 `engines: >=18` 的声明真正被验证。

## 已知限制（Known Limitations）

- **`claude plugin validate` 已通过真机校验**（含 `marketplace.json`），但**完整安装闭环
  尚未走通**。开发环境无法运行 `claude` CLI —— 它内部需要 spawn `reg.exe`，而该程序在
  安全策略黑名单上。需在真机执行：

  ```bash
  claude plugin validate .claude-plugin/plugin.json
  claude plugin marketplace add wychmod/test-generator
  claude plugin install testcase-generator@wychmod-testcase-generator
  ```
- **非 Claude 客户端尚无插件清单**：`.codex-plugin/` / `.cursor-plugin/` 等需要各厂商的清单
  规范，未在缺乏权威规范的情况下臆造格式。
- **`docs/` 不在任何一致性审计覆盖范围内**，仍存在 v2.1 叙述性引用。
- `skills/testcase-generator/knowledge/index.json` 是本地构建产物，不入包，首次使用需先重建。
- 未接入 `agnix` 等第三方 agent 配置 linter（与自研审计的重叠度待评估）。

## 升级注意（Upgrade Notes）

- **路径破坏性变更**：技能内容已迁至 `skills/testcase-generator/`。任何硬编码了
  `prompts/`、`resources/`、`templates/`、`config/`、`scripts/`、`knowledge/` 根路径的
  外部脚本、宿主配置或 CI，都需要加上 `skills/testcase-generator/` 前缀。
- **`openclaw` 本地激活目标已变更**（见上）。若曾在本仓库内跑过 `activate openclaw`，
  旧产物位于 `skills/testcase-generator/` —— 迁移后该目录是 canonical 内容，请勿与镜像混淆。
- `SKILL.md` 的执行细则已迁至 `references/`。宿主若缓存了旧版 `SKILL.md`，需重新激活。
- 版本号不要再手工修改：改 `skill.manifest.json` 的"版本"字段，然后回写。

  ```bash
  python devtools/sync_version.py --write
  ```
- `.claude-plugin/` 是生成物，不要手改；改 manifest 后跑 `gen_plugin_manifests.py --write`。
