# v2.3.1 — 质量体系自洽修复 + 两道可执行校验门禁

> 本版是 v2.3.0 的**修正版**，不引入新的方法论能力，只修掉质量清单与模板里
> 已经存在的自洽性缺陷，并把「文档自洽」与「用例产物验收」从人工核对变成
> 可执行脚本。

## 新增（Added）

- **`skills/testcase-generator/scripts/check_consistency.py`** —— 文档自洽性校验：
  每 Phase 权重和 = 100、组内检查项权重和 = 组声明权重、检查项 ID 唯一且符合
  `G<阶段>-<组>-<序号>`、```yaml 代码块可解析、Markdown 相对链接可达、
  `prompts/*.md` 的 `## N.` 章节编号连续。支持 `--strict`（有 Error 时非零退出）
  与 `--json`。
- **`skills/testcase-generator/scripts/check_artifacts.py`** —— 用例产物验收门禁：
  区分「用例定义」与「索引/追溯引用」并给出唯一用例数、必填字段完备性、
  安全类用例 CWE 标注、不可执行项必须显式 `SKIP/TBD` 不得伪装 PASS/FAIL。
  支持 `--self-test`（内置 9 组正反例）、`--baseline`（棘轮式防退化）、`--json`。
- **`test-plan.md` 之外的评测语义盲区声明**：`check_artifacts.py` docstring 明写
  5 条结构性盲区（只识别 `TC-` 前缀与三种载体、字段检查靠关键词、只抓显式标注的
  不可执行项、CWE 只查编号格式、不判断预期是否正确），防止把脚本输出当质量结论。
- **`devtools/capability_audit.py`** 必需路径新增 `check_consistency` /
  `check_artifacts` 两项（30 → 32 项）。
- **`DISTRIBUTION.md` / `skill.manifest.json` / `package.json`** 同步登记两个新脚本
  为运行时文件。

## 改动（Changed）

- **`resources/quality_checklist.md` 权重全面校准**：v2.3.0 的检查项权重合计 **527**
  而声明为 500，Phase 5 实际 523/100；本版按最大余数法逐组校准，使
  **每个 Phase 的组权重合计 = 100，且每组内检查项权重和 = 该组声明权重**。
  综合评分公式的分母由 `Σ(All_Weights)` 固定为 `/ 100`。
- **检查项 ID 命名空间统一**：Phase 1 原本使用两段式 `G1-1`，Phase 2 之后用三段式
  `G1-1-1`，15 个前缀同名；本版统一为 **组 `G<阶段>.<组>`**（点号）+
  **检查项 `G<阶段>-<组>-<序号>`**（两个连字符），并明确「不存在两段式写法」。
- **`prompts/phase3/phase4/phase5` 章节重编号**：三个提示词均缺 `§5`，导致
  `6.1`/`7.1` 等跨节引用对不上；本版重排为连续序列并修正全部跨节引用。
- **`prompts/phase0` YAML 内正则转义**：`pattern:` 的值由双引号改为单引号，
  避免 `\d`/`\s` 在 YAML 双引号里成为非法转义。
- **`prompts/phase1` YAML 缩进**：`default:` 块从 4 空格修正为 2 空格，恢复与
  `file_type_detection` 同级。
- **`prompts/phase4` 百分比字面量加引号**：`target: 100%` → `target: "100%"`，
  避免 `%` 触发 YAML 指令解析。
- **`scripts/incremental_code_scan.py` 显式声明能力边界**：docstring 注明规则扫描
  仅 4 条**文本模式**规则（无法识别语义缺陷，列出 4 类已知盲区），PRD 符合性
  按 token 重叠度做启发式匹配、`needs_review` 是正常输出而非失败；密钥正则扩展
  到 `MERCHANT_KEY` / `DB_PASSWD` / `sk_live_` / `AKIA` / `ghp_` 等前缀，
  裸 `except` 规则扩展到 `except Exception as e:` 这类过宽捕获。
- **`references/quality-gates.md` 引用修正**：原指向未分发的 `devtools/`，改为
  指向随包脚本 `scripts/check_consistency.py`，并保留「不随包分发」的说明。

## 修复（Fixed）

  `created_at: "{{ now }} registration_data:` 引号未闭合（合并了两行），

  `G2-1` 等全部改为点号组写法，与检查清单对齐。

## 移除（Removed）

无

## 已知限制（Known Limitations）

- `check_artifacts.py` 是**文本结构门禁**，不是评分器：不判断预期结果是否正确、
  不判断覆盖是否充分、不判断用例能否真的跑起来；对隐性不可执行项（标注为
  「结构验证」但实际需要读 DDL）无感知。
- `check_consistency.py` 的权重校验只覆盖 `resources/quality_checklist.md`，
  不覆盖 `docs/quality/quality-gates.md` 里的门禁摘要（后者靠人读对齐）。
- `pyyaml` 仍是**可选依赖**：缺失时 YAML 解析项降级为 WARN，不 fail。

## 升级注意（Upgrade Notes）

- **两段式 G 编号不再有效**：若你的项目里引用过 `G1-1` / `G2-3` 这种写法，
  迁移为 `G1.1`（组）或 `G1-1-1`（检查项）。`check_consistency.py` 会拦住旧写法。
- **评分分母变了**：`Phase_Score = Σ(权重 × 判定系数) / 100`，不再除以
  `Σ(All_Weights)`。若你的报表工具硬编码了旧公式，需要同步。
- **新增两个脚本自动随包**：`.skill` / `.zip` / npm / `activate` 四条通路都会
  带上 `scripts/check_consistency.py` 与 `scripts/check_artifacts.py`。
- 发版前建议在技能树目录执行：

```bash
cd skills/testcase-generator
python scripts/check_consistency.py --strict
```
