# v2.1.0 — 六阶段流水线 + 分发元数据

> **核心主题**：从「五阶段流水线 + 单点打包」升级为「六阶段流水线 + 多
> 宿主分发 + 治理元数据」。本版奠定了 testcase-generator 作为**可
> 拔插 Skill 包**的形态。

## 新增（Added）

### 流水线

- **Phase 0 输入预处理** —— 五阶段扩为六阶段的第一步。负责多格式解析
  （Markdown / PDF / Word / Excel / JSON / YAML / OpenAPI）、输入质量
  评分、歧义检测与缺口识别，并按增强建议回填用户输入后再交给 Phase 1。
  新增 `prompts/phase0_input_preprocessing_prompt.md` 详细执行协议。
- 阶段产物目录在 README 中明确从五阶段产物图升级为六阶段：
  `phase0/00_*.md` + `phase1/..5/0N_*.md`。

### 分发元数据

- **`skill.manifest.json`** —— 中英双语的分发元数据。声明：
  - 入口、说明、适用场景、核心能力、运行时文件清单、宿主适配入口
  - 强制排除清单（test-output / 镜像副本 / IDE 缓存 / 包中包）
  - npm 包名 / 命令 / 激活示例
- **`DISTRIBUTION.md`** —— 人工可读的分发清单与发布前检查项。
- **`HOST_COMPATIBILITY.md`** —— 宿主能力矩阵与降级说明。

### 多宿主适配

- **`adapters/` 目录** —— 统一收口多宿主入口：
  - `claude/SKILL.md`（薄适配）
  - `codex/AGENTS.md`
  - `qoder/SKILL.md`
  - `openclaw/skill.md`
  - `trae/SKILL.md`（v2.1 末段补齐）
- **`lib/activation.js` + `bin/test-generator.js`** —— npm 激活 CLI：
  `test-generator activate <environment> [-g] [--target <path>] [--dry-run]`

### 开发工具

- **`devtools/`** —— 把所有「打包 / 审计 / 验证」从根目录搬到子目录：
  - `capability_audit.py` —— 能力矩阵 / 必需路径 / 版本对齐 / Schema
    有效性 / v2.1 标记（6 项 token）审计
  - `skill_quality_audit.py` —— 用例必填字段 / 阶段流水线描述 / 标准
    引用（ISO/IEC/IEEE 29119-3:2021）/ 质量门禁 token / 输出评分审计
  - `package_skill.py` —— 替换 `run_package.bat`，统一打 `.skill` 与
    `.zip` 并交叉校验
- **`resources/output_artifacts.md`** —— 承接阶段产物的详细定义与命
  名约定，补齐 README 的简略产物图。

### 模板与资源

- 既有 `templates/`（requirements / state_diagram / testcase）与
  `resources/`（feedback / testcase_formats）补齐 v2.1 适配注释。
- **`config/testcase-config-schema.json` + `config/example-config.json`**
  —— 配置驱动生成；`capability_audit.py` 验证 schema 与示例配置可被解
  析且 `required` 字段对齐。

## 改动（Changed）

- 阶段语义从「五阶段」改为「六阶段」；README 中"五阶段流水线架构"文
  案更新为"六阶段流水线"，并补图。
- README 中质量门禁阈值表新增 Phase 0（≥ 80 分）。
- `test-generator` CLI 重新以 `lib/activation.js` + `bin/test-generator.js`
  模块化拆分，支持 `environments` 子命令列出全部宿主。
- `skill.manifest.json` 的"版本"字段由 `2.0.x` 升级到 `2.1.0`，并
  同步到 `package.json` 与 `SKILL.md` front matter。

## 修复（Fixed）

- v2.0.x 的「标准引用漂移」—— README / SKILL.md / 输出模板以前偶
  尔同时引用 IEEE 829 与 ISO/IEC/IEEE 29119-3:2021。本版统一以
  29119-3:2021 为现行标准，IEEE 829 仅作为历史兼容参考（由
  `skill_quality_audit.py` 的 `standard_reference` 检查兜底）。
- `prd_reader.py` 在宿主不支持 Python 时以前会硬报错。本版在
  `SKILL.md` / 各 adapter 中明确降级路径（纯文本分析模式），符合
  「可选依赖」铁律。
- `package_skill.py` 的 `FORBIDDEN_ARCHIVE_PATTERNS` 补齐
  `.workbuddy/` 与 `__pycache__/`，避免本地环境意外入包。

## 移除（Removed）

- 根目录 `run_package.bat` —— 已被 `python devtools/package_skill.py`
  替代，不再作为推荐入口。
- README 中"基于截图的 PRD 解析"宣传文案 —— 实现层实际不依赖视觉
  模型，避免误导。

## 已知限制（Known Limitations）

- **没有端到端 LLM 回归测试**：现有 `test/` 仅覆盖 `lib/activation.js`
  的纯逻辑（resolve target / collect runtime files / copy），不验
  证 prompt 真正按预期让 LLM 输出。Eval 流水线见 `.harness/eval/`
  （v2.2 计划）。
- **`prd_reader.py` 依赖第三方 PDF 库**：宿主若无 PyPDF2 / pdfplumber，
  走纯文本分析；未提供更细的 `Skill` 内降级文案。
- **未做 6 阶段产物格式的强校验**：`skill_quality_audit.py` 对
  `output_*.md` / `*.feature` / `*.yaml` 文件做了轻量打分，但对
  Phase 3 / Phase 4 的领域模型 / 状态机图没有 SVG / Mermaid 块的强制
  要求。

## 升级注意（Upgrade Notes）

- **入包边界**：
  - 本版新增 `.codebuddy/`、`.cursor/`、`.windsurf/`、`.openclaw/`
    等多个宿主镜像目录（部分由后续 2.2 计划补齐），发布前请确认它们
    都在 `skill.manifest.json` 的"分发排除"里。
  - `test-output/` 仍然不能入包；该规则被 `devtools/package_skill.py`
    强制检查。
- **版本号三处一致**：升级时**同时**更新 `SKILL.md`（`version:`）、
  `README.md`（标题）、`skill.manifest.json`（"版本"）。
- **CLI 入口**：从直接调 `bin/test-generator.js` 改为 `npx
  test-generator ...`，或全局 `npm install -g testcase-generator-skill`
  后调 `test-generator ...`。
- **配置 schema**：v2.0 用户如果用过 `config/example-config.json` 的
  自定义变体，升级后请用 v2.1 的 schema 重新校验
  （`capability_audit.py` 会做这件事）。
- **adapter 内容迁移**：v2.0 期间某些 adapter 把 prompt 内容复制到了
  本地，本版起统一禁止（`AGENTS.md` §4.3 薄适配铁律）。如有遗留复制
  内容，请在升级时清空。
