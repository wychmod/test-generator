# 项目规范与约定（示例）

这是 testcase-generator 知识库的示例项目规范文件。**用户应替换为自己的项目规范**。

## ID 命名规范

- 用户 ID：`UID-{6位数字}`，例 `UID-000123`
- 订单 ID：`ORD-{yyyymmdd}-{8位流水}`，例 `ORD-20260613-00001234`
- 交易 ID：`TXN-{yyyymmdd}-{8位流水}`，例 `TXN-20260613-00005678`
- 测试用例 ID：`TC-{模块}-{子模块}-{3位序号}`，例 `TC-AUTH-LOGIN-001`

## 错误码约定

错误码为 6 位数字，按模块划分：

| 前缀 | 模块 | 示例 |
|---|---|---|
| 10xxxx | 用户与认证 | 100001 = 用户名已存在 |
| 20xxxx | 订单 | 200001 = 订单不存在 |
| 30xxxx | 支付 | 300001 = 支付失败 |
| 40xxxx | 商品 | 400001 = 商品已下架 |
| 50xxxx | 系统 | 500001 = 内部错误 |

错误响应格式：
```json
{
  "code": 100001,
  "message": "用户名已存在",
  "trace_id": "abc-123-def"
}
```

## 时间格式

- 所有时间戳统一使用 ISO 8601 + UTC：`2026-06-13T10:24:20Z`
- 数据库存储使用 `DATETIME(3)`（毫秒精度）
- API 返回时根据 `Accept-Language` 决定是否转本地时区

## 密码强度规则

- 最少 8 位
- 必须包含：大写字母、小写字母、数字
- 允许特殊字符
- 不能与最近 3 次密码相同
- 不能包含用户名

## Token 规则

- Access Token 有效期：30 分钟
- Refresh Token 有效期：7 天
- 单点登录：同一用户在新设备登录会踢掉旧设备
